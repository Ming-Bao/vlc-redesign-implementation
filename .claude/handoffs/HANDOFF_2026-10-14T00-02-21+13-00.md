## Session goal
Implement slice 3 of the Figma redesign (the vertical tracks and playback panels), then the features the user added: an "add folder" option in the queue, click to pause, per-file memory of video/audio/subtitle tracks, and resuming the last session (queue + position) on startup. Figma file `dSoAm0gN9ZterHSssJU9FN` plus `redesign source.mp4` are the spec; VLC 4's own design is not a reference.

## Decisions
- Panels: one reusable `PlayerPanel.qml` (T.Popup, 400 px card at the bottom right) with `TrackSection.qml` lists and `TracksPanel`/`PlaybackPanel`. Rejected keeping TracksMenu because Figma is the spec.
- The playback panel has one tab with Reverse, Visualizer and Speed. A Figma-style 0.25–2 slider replaced PlaybackSpeed.qml, because that widget brings its own title and a presets grid Figma doesn't have. Subtitle timeline, statistics and sleep timer are omitted because VLC has no such features.
- Panels are `modal: true`, `dim: true`, with `T.Overlay.modal: Item {}`. They close on `Overlay.overlay.released()` unless `cardHover.hovered` (the HoverHandler on contentItem) or another QQuickPopupItem is open. Without modal+dim, Qt passes the dismissing press through to the video, which pauses it; closing on press or using CloseOnPressOutside both leaked the click.
- Keys inside any popup bypass player hotkeys (`InterfaceWindowHandler::applyKeyEvent` walks the parents looking for QQuickPopupItem). The alternative of forcing TabFocusReason showed a focus ring on mouse open.
- Click to pause uses the core's existing feature (`mouse-pause-policy`). My QML version was reverted because it double-toggled with the core and ignored the preference. The real bug: the MKV demux took over the mouse callback for every MKV file, so it now does so only when `has_dvd_menus`.
- User choices (via AskUserQuestion): on startup **restore paused**; for any file **always resume** with no prompt. Implemented as core defaults `restore-playback-pos=ALWAYS` and `restore-playback-states=true`.
- Session restore lives in Qt QSettings (`PlaySession/Items|Current|TimeMs`), not an m3u. It is snapshotted at the top of qt.cpp `Close()`, because ThreadCleanup stops playback before `app.exec()` returns. It is restored only when the playlist is empty (command-line files are added before the interface starts) and no crash-recovery file exists.

## Bugs / issues surfaced
- **Next-item crash (OPEN, mid-investigation).** Switching to the next video segfaults with heap corruption, detected in the freetype text renderer's Destroy (FcConfigDestroy / FT_Done_FreeType) in `spu_Attach` during vout reuse.
  - Reproduced 0/4 survivals with `restore-playback-states` on, 4/4 with it off.
  - Cause: `vlc_player_input_RestoreMlStates` reset vout vars (zoom, aspect, deinterlace, video-filter) on every new input while the vout was being reused.
  - Fix in the working tree (uncommitted): apply only saved states (`has_vout_states`); measured 4/4 survivals.
  - **The working tree currently contains an un-reverted isolation test** at `src/player/medialib.c:104-107` (`(void)has_vout_states;` plus `var_SetString(vout,"video-filter",NULL); /* ISOLATION TEST */`). Restore it with `cp /tmp/ml.bak src/player/medialib.c` (or re-apply the fix by hand). The underlying vout-var race still exists for media that do have saved vout states.
- **Autoresize assert (`video_window_handler.cpp` `dW >= 0 && dH >= 0`).** The window gets resized before the scene re-lays out. Fixed in the working tree (uncommitted) by keeping the last valid compensation in `m_sizeCompensation`; this is upstream code.
- **Track choices never saved (FIXED, e68cd7f5da).** Tracks were unselected and deleted before `UpdateMLStates` ran. They are now recorded per category in `input->ml.user_track_ids` when the user picks them. Choosing "None" for subtitles is still not persisted (core limitation).
- **ComboBoxExt broken on master (FIXED, 5587abf692).** Upstream fc71047387 dropped the Controls import. ToolbarEditorDialog.qml:115 is still broken for the same reason (bare ItemDelegate).
- **Toolbar FSM (FIXED, 25d2e299e6).** The Hidden state ignored lock(), and the startup lock was dropped, so menus closed by themselves.
- Pre-existing: `PlaylistButton.qml:34 ReferenceError: playlistWidget` (upstream); libmedialibrary segfaults in its global destructor on SIGTERM exit.
- **Harness played audible test tones** through the user's speakers (they were annoyed). Both drivers now pass `--aout=dummy` (uncommitted); recorded in memory `redesign-harness.md`.
